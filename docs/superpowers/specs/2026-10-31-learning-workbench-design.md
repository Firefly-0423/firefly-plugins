# Firefly 多语言学习工作台设计

状态：用户于 2026-10-31 授权先实现并查看运行效果，接受后提 PR 至 main；实现与验证见配套计划和 validation 报告，尚未发布。本文按用户选中的 Yomitan 方向设计，不使用此前已关闭的字幕/颜色或地图/时间线提案。

## 目的和范围

用户希望把“阅读外语时弹出词义、发音、导入词典、收集生词”做成学习插件，语言范围为热门语言。首版提议覆盖英语 en、日语 ja、韩语 ko、法语 fr、德语 de、西班牙语 es，默认中文界面。这个六语言清单和下面的实现选择是本轮建议，不表示用户已逐项批准。

核心流程：在 Firefly 学习窗口阅读文章 → 选择词语 → 弹出词典释义 → 听发音 → 选择释义并保存生词和上下文 → 复习。没有词典/匹配项/可用发音时显示真实状态，不编造释义或读音。

首版划词作用于插件自己的阅读区。公开 SDK 没有浏览器扩展式的任意网页文字注入接口，所以不宣称支持直接在 Chrome/Edge 的任意网页划词。配套浏览器扩展属于后续独立范围。

## 方案与推荐

1. **升级现有 study-cards（推荐）**：保留插件 ID 和七个既有工具，增加学习窗口、词典、生词与阅读；原卡片继续可用，用户不需要管理两套复习库。
2. 单独新建 learning-reader：可独立发布，但当前 SDK 没有跨插件调用/数据共享契约；连接 study-cards 需要显式导入导出或扩展公开接口，不能偷偷读取另一插件存档。
3. 直接安装 Yomitan/另做浏览器扩展：能提供浏览器原位体验，但不等于 Firefly 原生插件，且需要另一套扩展安装、权限和通信流程。

推荐方案 1，拟把 study-cards 从 0.1.1 升至 0.2.0，显示名称改为“语言学习”。这是待确认的升级选择，不立即修改现有插件。

## 使用界面

窗口四个入口：阅读、生词、复习、词典。

- 阅读：粘贴文章，或用原生选文件对话框打开 UTF-8 .txt/.md；用户明确选择原文语言。原文只作文字渲染，Markdown 首版不执行 HTML。记住阅读位置，选词后就近弹出结果，Esc 关闭、键盘可操作。
- 查词卡：显示原词、词典词头、读音字段、释义、词典名/版本及释义语言。多个词典按用户排序，点击展开其他来源。保存时选择一条释义，截取当前句子，允许编辑后再确认。
- 生词：按语言、来源、牌组和状态筛选；可编辑释义与例句、删除、播放可用读音、跳回保存时的文章片段。相同词/语言/释义重复收集时提示已有项目，可增加例句，不默认重复造卡。
- 复习：复用既有新卡/到期卡/四档评分规则，先显示词或例句，再揭示答案；只按用户选择写评分。不是 Anki/FSRS 算法，不引入外部 Anki 数据。
- 词典：导入、查看来源/许可说明、启停、优先级和删除。显示导入条数、被拒绝/不支持条目、实际占用和结果，不能仅有“完成”提示。

文章不自动抓取远程网址；不会在有主进程权限的页面加载任意外语网站。后续网页导入另行定义网络权限和内容清理。

## 六种语言的实际支持

六种语言都必须完成选区文本查词、词典语言筛选、读音展示、生词收集和复习。查词首版以明确选词的精确匹配为基础：NFC Unicode 规范化、Latin 大小写候选（原词结果优先），不使用破坏重音的通用去音符规则。

不把六个语言下拉框等同于完整分词/词形还原：首版不承诺所有动词变位、日语活用、韩语词尾或自动悬停分词。词典中已有变形词条可正常命中；未命中时提示尝试原形或调整选区，不自行生成并展示“猜出来的词义”。每种语言的形态处理能力应在词典页明确列出；后续若引入规则，必须独立测试正确候选与误匹配。

默认中文是界面语言，不保证所有语言都有同等覆盖的中文释义词典。显示词典 sourceLanguage/targetLanguage；英语释义明确标注“英文释义”，不伪装成中文翻译。首版不隐式发送文章给翻译模型。可在后续通过正式 llm 服务增加“解释这句话”，但需要另行适配仓库目前拒绝非空 deps 的打包约束。

## 词典数据和授权

参考 Yomitan 公开格式：ZIP 根目录 index.json 与 term_bank_N.json（format 3）。程序独立实现格式支持，不复制 GPL 源码；任何未来复用须另做来源、许可及分发核对。词典各有自己的许可，不因 Yomitan 开源而自动获得打包分发权。

不内置未经授权的大词典或自动下载地址。提供原作者编写的小型演示词条，显式标明“演示词典”，以及指导用户导入本地合法词典的入口。真实语言验收仍需每种语言至少一份可合法测试的真实词典，演示数据不能替代覆盖验证。

初版支持文本释义，及受限结构化释义的安全文本化（保留换行、列表、表格的文本顺序）。不加载词典内 styles.css、脚本、HTML 或外部 URL；不支持的图片/媒体与元数据要在导入前报告。会丢失核心释义的条目不按成功导入计算，用户可取消整次导入；没有警告的情况下不得静默删字段。词频、音调、笔顺和完整 Yomitan 图像排版不属于首版保证。

ZIP 必须在后台逐条有界解压，拒绝路径穿越、绝对路径、链接、重复/大小写别名、加密条目与超额展开。拟定限额：压缩包 200 MiB、总展开 1 GiB、单 bank 64 MiB、最多 2 百万词条；这些是设计上限，需通过实现时真实数据性能验证才能定为正式产品限制。压缩头给出的大小不是可信的唯一检查；实际读取的解压字节也要累计计数，超过即取消。

导入采用 staging 和独立索引，成功校验后才切换当前词典集合；失败、取消和停用不能破坏现有词典。ZIP 库要以固定版本和完整许可随包提供可读运行源码，不在运行时 npm install，不依赖宿主未公开的压缩模块。具体读取库和分片策略交由实现计划核对，不在此预先增加依赖或放宽构建限制。

## 发音

词典的 reading 字段首先作为文字读音展示。合成朗读优先使用运行环境实际列出的、语言匹配且标记为本地的系统语音；UI 标注“合成朗读”。无可用语音则禁用并解释，不伪装已播放，不把另一语言的声音静默替换过来。切换词条、关弹窗或停用插件时停止播放。

已核对 SDK 没有公开 TTS 服务；不能直接调用 Firefly 内部配音模块或承诺流萤声线。Electron SpeechSynthesis 的本机语音可用性、沙箱中播放及多语种声音列表必须在实现前做小型探测；如果不满足，先保留明确的 unavailable 状态，不能暗中联网兜底。

原版 Yomitan 还支持多个外部真人发音源。该链路首版不启用：涉及服务条款、覆盖、网络授权和音频来源验证，后续再做用户可配置方案。

## Firefly 接口和本地数据

使用 register(ctx)、unregister、open()、ctx.registerTool、ctx.onDispose 和 ctx.storage.rootDir()。保留现有 study-cards 工具 ID/参数/返回主字段；新增只读查词接口和有版本检查的收词入口。所有工具由宿主审批调度，读写风险如实声明。

拟新增工具：study-cards_lookup({language,term,limit?})、study-cards_collect({language,term,reading?,meaning,context?,dictionaryId?,operationId})；这些尚未实现，字段最终由实现计划及测试确定。查词不能读取其他插件数据或任意路径；词典导入只从窗口的文件授权入口进行，模型不能提交任意本机路径。收词不得把当前整篇文章自动交给模型。

词典查询和导入在 worker 中运行，UI 与 Main 不做大型同步 JSON/SQL 操作。SQLite 使用参数化语句；用户和词典内容不能成为 SQL、脚本或可执行 HTML。未完成的旧查询以 requestId 作废，不把前一个词的结果刷到后一个词上。

已对当前 Electron 43.7.0 / Node 24.21.0 执行只读运行时探测，node:sqlite DatabaseSync 可用。后续必须在正常 Electron 主进程及 worker 再验一次；不把 Electron-as-Node 的探测等同于整个产品验收。缺少内置 SQLite 的旧运行时应给出明确兼容错误，不下载其他运行时。

提议使用学习数据 SQLite（文章、生词、卡片、评分操作去重）及独立的只读词典索引库。ctx.storage 用于小配置，所有数据库都在插件私有目录中。

兼容原卡片：升级时读取现有 cards-v1.json；校验通过后以数据库事务导入，保留原卡片 ID、revision、牌组、dueAt、interval 和 reviews，不改复习规则。迁移成功标记与导入一起提交。旧 JSON 保留原样，不删除或反复导入；损坏的旧存档拒绝迁移，不视为空库。关闭或失败时事务回滚。降级到 0.1.1 只会读取旧 JSON，不能获得新修改，必须在更新说明中明确不支持无损降级，并提供新数据导出。

生词与卡片创建在同一学习库事务中完成，以 operationId 去重；避免跨 SQLite/JSON 双写导致重复卡或半个生词。更新/删除/评分继续要求 expectedRevision。读取分页，写入失败保守区分 not_applied 与 unknown；不自动重试未知写入。

数据库、词典和文章内容默认只在本地使用。只有用户在对话中调用工具返回的选定内容会进入该对话模型，不将阅读内容默认注入每轮提示词。

## 窗口、资源和工程形式

使用隔离 BrowserWindow，nodeIntegration:false、contextIsolation:true、sandbox:true；只加载包内资源，通过窄 preload 及已验证 sender/frame 的 IPC 暴露功能。所有辞书内容按文本或严格受限节点渲染。拒绝窗口跳转、弹窗、WebView 和默认网络请求，清理所有句柄/worker/语音。

沿用原仓库 manifest、LICENSE、README、catalog 和默认停用规范。UI/worker/可读库通过现有 package-files.json 显式列出；保留原资源限额和源码可读要求。主进程插件仍以应用权限运行，不能称为整个插件处在 OS 沙箱。

拟增加版本到 0.2.0；尚未改变 manifest、registry 或旧插件包。最终源码、设计、迁移测试和界面验证进入实现 PR，不发布 Release。合并后按既有要求仅保留 main，清理分支前确认全部插件与用户数据材料已保全。

## 实施顺序与验收门槛

1. 确认本设计及升级 study-cards 的选择。下一步才形成任务计划，不先复制原浏览器扩展或引入依赖。
2. 技术探测：正常 Electron worker SQLite、本地声音列表/播放、ZIP 有界读取、所选真实词典的体积和字段覆盖。
3. 本地核心：旧卡片事务迁移、词典 staging/索引/精确查词、词典来源/许可元数据、生词与卡片原子收集/幂等写入。
4. 阅读/选词弹窗/词典管理/生词/复习窗口，先有可操作的固定样本预览，再进行真实包验收；预览明确标注示例，不冒充真实词典结果。
5. 每种语言验证正常词、Unicode/组合字符、大小写/重音、短语、找不到的词、结果乱序取消；检查来源和释义语言正确。复杂词形不属于已实现范围时，必须显示未命中，不假造成功。
6. 安全与数据测试：ZIP 炸弹/穿越/重复条目、恶意释义/样式、超限、取消、导入故障回滚；旧 cards-v1 损坏保护/崩溃后重启/重复迁移；收词和评分重复请求、并发 UI/工具 revision 冲突、注销清理。
7. 实包：Firefly 安装器默认停用、启用/窗口、六语言实际词典查词、真实可用语言发音、收词后重启复习和导出。无本地声音的语言验证正确的不可用提示，不计为发音验收成功。
8. 运行项目现有 test/build/check 与 Windows/Ubuntu CI，核对其他插件包哈希不变。完整真实词典与 UI 结果应独立于单元测试记录，未完成项不得合并称“全部通过”。
