# 地点工作台与交互时间线：候选设计

状态：提案，待选择与确认。没有新增插件代码。以下名称、工具 ID、文件格式和上限均是设计建议，不是当前 Firefly 已提供的能力。

## 一、地点工作台

### 对应项目和具体使用过程

参考 [esm7/obsidian-map-view](https://github.com/esm7/obsidian-map-view)。用户创建“周末出行”项目，手工添加或让流萤录入已知地点，按“第一天/第二天”分组，在同一地图中查看地点和备注；点击地点可继续编辑说明，AI 也可以读取并调整同一个项目。

区别于一次性输出旅行建议：地点有稳定 ID、坐标、分组、资料来源和版本，修改后仍然可打开。插件不替代交通导航或票务服务。

### 首版范围

- 独立窗口，地点列表、地图画布和详情面板。支持添加/修改/删除点、分组、搜索项目内地点，保留原始来源 URL 作为可点击资料。
- 地点使用用户提供的经纬度，不自动猜坐标。首版不承诺地址搜索、实时路况、酒店搜索或最优路线。
- 项目保存在插件私有存储；可选导入/导出有界 GeoJSON Point 数据，文件通过原生对话框授权。轨迹、GPX、KML 与离线瓦片下载后续单独评估。
- 地图瓦片按用户明确选择的服务使用，显示许可署名。未配置时可编辑地点列表，不用空白画布假称真实地图。瓦片请求会暴露浏览区域，配置前明确说明；不隐藏联网行为。

### Firefly 适配建议

- 拟用 `places-workbench` 作为插件 ID，仍需实现前核对重名。
- `register(ctx)` 注册 `places-workbench_read` 和 `places-workbench_apply`；`open()` 打开独立窗口，`unregister()` 清理窗口、IPC、请求和工具。沿用已有 package-files.json 显式声明 UI 资源，不调用 Obsidian 服务。
- `read` 提供分页地点与 revision；`apply` 提供结构化点/分组操作，已有项目必须带 expectedRevision。人和 AI 共用同一数据服务；界面有未保存修改时拒绝 AI 覆盖。
- 项目存储使用 `ctx.storage`。工具风险按实际读写声明，文件导入导出另做大小、路径、格式和原子替换保护。不得假设 `workspace.getBinding()` 就授予了文件访问权。
- 地图渲染候选为 Leaflet；不是安装整个 Map View。实现前核对渲染器及所有附属资源许可、可读打包大小和隔离窗口 CSP。

### 数据与验收

拟定项目字段：version、projectId、revision、groups、places；地点含 id、label、latitude、longitude、groupId、notes、source。纬度[-90,90]、经度[-180,180]；拒绝重复 ID、未知组、非有限数和无效数据。建议每项目最多 1000 点、每次最多 100 个操作；超限整批拒绝。

验收应包含：真实 ZIP 安装与启停；创建两日旅行项目；手工和工具修改同一个地点；重复提交/过期 revision 拒绝；文件导入失败保持原项目；存储失败不报成功；瓦片失败有可见状态；停用后取消请求；经用户配置后的服务真实连通。没有接入地图服务前，不声称完成地图显示验收。

## 二、交互时间线（建议先做）

### 对应项目和具体使用过程

参考 [rborisov/vis-timeline](https://github.com/rborisov/vis-timeline)。用户创建“项目进展”或“事件资料”时间线，输入日期、事件、区间和来源，按不同人物/主题分行查看；拖动和缩放查看前后关系，点击事件打开详情。让流萤整理资料时生成的是可继续编辑的事件记录，而不只是一段文字。

它展示事件关系，不负责执行定时任务，也不替换 Firefly 的核心记忆。排期提醒若以后需要，应调用已有宿主调度，而不是另写调度器。

### 首版范围

- 独立本地窗口：时间刻度、事件分组、点事件/日期区间、详情编辑、缩放及筛选。
- 用户创建/编辑/删除/移动事件；流萤通过结构化工具读写同一项目。提供来源链接和备注字段，点击前不自动抓取页面。
- 日期先接受明确的公历 ISO 日期和必要的日期区间，不推断模糊“去年春天”，不将不确定日期伪装成精确日期。只记录日期的事件不因本机时区发生一天偏移。
- 用户可保存本地项目并导出 JSON/Markdown。首版不支持 BCE、自然语言自动抽取、多用户协作、自动监控资料更新或聊天内部嵌入。

### Firefly 适配建议

- 拟用 `event-timeline` 作为插件 ID；实现前核对名称。
- 注册 `event-timeline_read`、`event-timeline_apply`；`open()` 打开窗口。UI 修改和工具写入共用一个事务服务，全部记录 revision。
- 首先使用插件私有存储，减少工作区文件授权范围。导入/导出需要用户选文件；成功返回真实输出路径和结果，不能把 UI 预览当成已保存。
- 上游入口直接依赖 Obsidian 的 markdown code-block processor 和 Bases view；这些部分必须替换，不能复制后视为 Firefly 兼容。
- 上游 package/LICENSE 的许可不一致尚未解决，当前不计划复制上游代码。可以独立实现公开工作流；若选用 vis-timeline 渲染库，必须另核对库本身的许可、大小、HTML 内容消毒和延迟加载，不能把插件许可当成依赖库许可。

### 数据与验收

拟定事件字段：id、title、startDate、endDate?、groupId?、notes、source；项目另有 version、projectId、revision、groups。日期严格校验，结束不得早于开始。建议每项目最多 1000 事件、单批最多 100 操作，拒绝重复 ID 和不存在的组。标签作为文本渲染，不执行事件内容里的 HTML/脚本。

验收任务：导入或创建十个事件，包含同时发生、跨月和闰日区间；按组查看；工具修改后窗口同步；手工草稿未保存时阻止覆盖；过期 revision 和重复请求不重复修改；保存并重开顺序/日期正确；时区切换不改变日期；输出 JSON/Markdown 和原项目一致；停用/重启和损坏存档保全。

## 三、工程形式与推进顺序

两个候选均遵守 Firefly manifest、默认停用、插件前缀工具、生命周期、来源许可、catalog 和行为测试规范。由于目标是可编辑工作台，需要 UI 资源，而不是强行改成原五插件的四文件算法。现有 DrawAI 的资源打包形式可作为接入先例，不默认共用其内部文件服务。

先由用户选择地点工作台或时间线，并确认实际使用任务；再形成实现计划，确定数据/窗口/权限细节，编写测试和代码，最后提交实现 PR。此设计 PR 不代表已经开发、安装、发布或完成上述验收；也不修改市场安装接口。
